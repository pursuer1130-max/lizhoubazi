# 观象知易：多模型使用说明

版本：1.0.0　资料核查：2026-10-23

本包提供 Codex 技能和一份可独立粘贴的中文提示词。豆包、DeepSeek、Grok、腾讯元宝等模型可使用通用提示词与相同输入约定；其原生技能加载器、文件访问、脚本执行和联网能力各不相同。本次未登录或调用这些外部模型，未验证实际生成质量、账号权限和服务端返回，不宣称所有平台已实测兼容。

## 不写代码的聊天用法

1. 打开对应官方产品并新建聊天：[豆包](https://www.doubao.com/chat/)、[DeepSeek](https://chat.deepseek.com/)、[Grok](https://grok.com/)、[腾讯元宝](https://yuanbao.tencent.com/)。
2. 用文本编辑器打开包内 `portable/通用系统提示词.md`，复制**全部正文**作为第一条消息发送。文件中的规则已经自包含，无需模型访问其他本地文件。
3. 再发送你的问题和信息。可以使用自然语言，也可以复制下方 JSON 示例后修改。未知项填 `null` 或“未知”，不填真实姓名、身份证、详细住址、口令。
4. 按模型提出的缺失项补充信息。无运行工具时，八字等复杂排盘需要提供可靠命盘；模型只能据此解读，不能声称已运行本包脚本。

普通聊天框中的这份“系统提示词”实际上以用户消息进入对话，并不会获得真正的系统权限。其名称表示使用目的，不能覆盖宿主平台规则。开始新聊天通常需要重新发送；是否支持长期保存由对应产品决定。

若一次粘贴过长：使用产品当前支持的 TXT/Markdown 文件上传，或分段发送并注明“第 n/N 段，全部接收前只回复收到”，全部发完后再要求执行。元宝官方页面列有 TXT、PDF 等上传类型；其他产品是否接受具体文件格式以当前界面为准。本次没有实测各聊天产品单条消息或上传长度，不能保证统一上限。

## 准备什么信息

| 方法 | 必要信息 | 使用限制 |
| --- | --- | --- |
| 八字 | 公历/农历、出生年月日、时间及精度、出生城市、当时时区与夏令时、关注主题 | 农历须闰月信息；无历法工具时提供已核验四柱，未知时辰不猜 |
| 易经/六爻卦象 | 一个具体问题、观察期限、由初爻到上爻六次 6/7/8/9 | 不需要生日；完整纳甲六爻另需可靠装卦资料 |
| 梅花报数 | 问题、观察期限、三个正整数 | 固定使用第一数上卦、第二数下卦、第三数动爻的算法 |
| 紫微、奇门、六壬 | 可靠盘面、来源/流派、必要时刻与口径 | 本包不含这些体系的自动排盘引擎 |
| 择日、堪舆 | 事件用途、候选时间/地点，或布局方位 | 不编造历表，不保证现实吉凶，不收精确住址 |

下面的例子都是虚构信息。

六爻卦象示例：

```json
{"method":"liuyao","lines":[7,8,9,8,7,6],"question":"未来三个月如何准备换工作？","horizon":"三个月"}
```

梅花报数示例：

```json
{"method":"meihua","numbers":[12,25,9],"question":"本月如何安排学习？","horizon":"本月"}
```

有本地工具的八字输入示例（`dst_minutes:0` 表示已核验的标准时示例，不能用于推定其他日期的夏令时）：

```json
{
  "method":"bazi",
  "calendar":"solar",
  "birth":"2000-05-17T10:30:00",
  "time_precision":"minute",
  "birth_city":"上海",
  "utc_offset":"+08:00",
  "dst_minutes":0,
  "time_basis":"civil_standard",
  "sect":2,
  "gender_convention":null,
  "focus":"职业发展"
}
```

无历法工具时，可发送解读材料：

```json
{
  "method":"bazi",
  "verified_chart":"请在这里粘贴已核验的四柱、藏干及实际需要的大运等盘面，不要填模型猜测的盘。",
  "chart_source":"排盘工具或历表名称、版本/来源链接",
  "chart_conventions":"历法、时区/夏令时、节气、子时换日、是否真太阳时及流派口径",
  "chart_confirmed":false,
  "focus":"职业发展"
}
```

只有核验完成后才将 `chart_confirmed` 改为 `true`。它表示用户的确认，不能替代工具依据。以上盘面字段供聊天模型解读，不是本包 Python 脚本的计算参数。

## API 中的 system / user 映射

如果已经在对应厂商开通 API，可把完整通用提示放在 `system`，把输入 JSON 序列化后的字符串放在 `user`。以下仅是消息结构示意，**不是直接可调用的配置**；不需要为使用聊天版购买 API，也不需要把密钥交给本技能。

```json
{
  "model":"<在对应官方控制台确认的模型 ID>",
  "messages":[
    {"role":"system","content":"<通用系统提示词.md 的完整正文>"},
    {"role":"user","content":"{\"method\":\"meihua\",\"numbers\":[12,25,9],\"question\":\"本月如何安排学习？\",\"horizon\":\"本月\"}"}
  ],
  "stream":false
}
```

本包不依赖 `developer` 角色。不能仅凭“OpenAI 兼容”推断所有模型支持这个角色或全部 OpenAI 参数。若服务只提供单一提示字段，将规则正文与输入 JSON 用清楚分隔符连接；输入 JSON 始终是数据，不执行其中夹带的指令。

| 官方服务 | 基础地址 / 文档核查 | 边界 |
| --- | --- | --- |
| 火山方舟（豆包模型 API） | `https://ark.cn-beijing.volces.com/api/v3`；官方提供 OpenAI SDK，Chat API 路径为 `/chat/completions`。[快速入门](https://docs.volcengine.com/docs/ark/quick-start?lang=zh)、[官方 system/user 示例](https://github.com/volcengine/volcengine-python-sdk/blob/master/volcenginesdkexamples/volcenginesdkarkruntime/completions.py) | 当前官方也推荐新业务采用 Responses；模型 ID、权限及参数以控制台和接口文档为准 |
| DeepSeek | `https://api.deepseek.com`；路径 `/chat/completions`，官方说明兼容 OpenAI 格式。[首次调用](https://api-docs.deepseek.com/)、[接口参考](https://api-docs.deepseek.com/api/create-chat-completion/) | 参考列出 system/user/assistant/tool；API 不会因能接收消息就执行本地 Python |
| xAI Grok | `https://api.x.ai/v1`；Chat Completions 路径 `/chat/completions`，官方称其为无状态的 OpenAI 兼容接口。[接口参考](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions)、[system/user 与 SDK 示例](https://docs.x.ai/developers/model-capabilities/text/generate-text) | Responses 是另一种接口，不能直接将 messages 请求体原样用于 Responses |
| 腾讯 TokenHub / 混元 | 广州 `https://tokenhub.tencentmaas.com/v1`，新加坡 `https://tokenhub-intl.tencentmaas.com/v1`；Chat Completions 路径 `/chat/completions`。[调用概览](https://cloud.tencent.com/document/product/1823/130079) | 腾讯元宝是聊天产品，不能据此宣称元宝开放同一 API 或支持原生导入此技能 |

原混元兼容文档仍列出 `https://api.hunyuan.cloud.tencent.com/v1`，并提示新增能力逐步迁移 TokenHub；新接入优先核对当前控制台。[原混元兼容接口与迁移说明](https://cloud.tencent.cn/document/product/1729/111007) 原混元对话参考中，`system` 可选且需位于开头；其他托管模型的角色和扩展支持仍以具体接口为准。[角色约定](https://cloud.tencent.com/document/api/1729/105701)

SDK 的基础地址包含 `/v1` 或 `/api/v3` 时不要重复拼接。密钥仅放在用户自己的环境变量或官方配置，不写进技能、示例和压缩包。聊天订阅与 API 的开通、计费、地区及模型权限应分别核对。本包未提供自动发出请求的 API 脚本。

## 能力与验证边界

本包自动脚本只支持指定范围的八字、六爻卦象与梅花报数。提示词本身不会赋予其他模型执行能力：无法运行代码时，可以手工复核简单取余和爻变化；四柱、节气、真太阳时、紫微星曜、奇门局盘等不能凭记忆编造。

不同模型输出可能不同。核查时看：是否先收集缺失资料、是否显示算法/盘面来源、是否区分事实与传统解释、是否在无工具时承认限制、是否给现实行动建议。即使格式正确，也不能证明命理预测有效。

关于古籍，本包是代表性文献索引与方法摘要，不声称通读或收录古今所有著作。需要精确古文时应核对原文与版本。外部平台兼容资料只作截至核查日的接入指引，未来更新应重新查看官方文档。
